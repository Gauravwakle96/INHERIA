# Unaided handover task pack

Use this with consenting people unfamiliar with INHERIA. These tasks and the
recording template are preparation material; no participant outcome is claimed.
Share the product link and task goal, then observe without a click-by-click
walkthrough. The application's built-in guide remains available.

## Tasks

1. **Understand the completed transfer.** Open the judge workspace. Identify the
   incoming owner, inspect evidence for one responsibility and identify an open
   operational problem. Explain why a completed handover does not mean that the
   underlying production incident is solved.
2. **Prepare a fresh handover.** Use the fresh entry. Reconstruct its sources,
   inspect and review supported knowledge, generate the handover and propose an
   incoming responsibility. Identify what still blocks closure.
3. **Resolve missing access.** Restrict a required source as coordinator. Switch
   to the successor, request missing knowledge access, then independently review
   that request. Determine whether this grants AWS access.
4. **Recover incomplete validation.** Submit an incomplete walkthrough as the
   successor. Have the coordinator request correction; resubmit and reassess.
   Explain who can approve the exercise and what prerequisite remains.
5. **React to changed evidence.** Replace an uploaded document. Inspect its
   downstream impact and determine whether old approval is sufficient. Find the
   next review/revalidation action.

Assign a representative subset per participant if time is limited. Record the
denominator; do not imply every person completed all five tasks.

## Observation record

| Field | Actual observation to record |
| --- | --- |
| Participant | Consenting anonymised label; relevant role and prior familiarity |
| Session | Date, device/browser and application commit/version |
| Task | Exact goal and which workspace mode was used |
| Outcome | Completed unaided, completed with help, or not completed |
| Time | Start/end or elapsed time; record waiting separately |
| Confusion | What the person misunderstood or could not locate |
| Assistance | Every hint or demonstration supplied |
| Consequence | Incorrect approval, missed blocker, accidental repeat or other issue |
| Fix/retest | Concrete change and observed result of repeating the task |

Save short notes without recording passwords, confidential sources or personal
conversations. Stop when a participant chooses to stop. Distinguish participant
actions from prerecorded example history and automated browser tests. Do not
fill these fields with assumed success or use a test run as a human session.

## Completion checks

Participants should be able to identify ownership, inspect a supporting source,
distinguish pending/verified knowledge, explain an unresolved blocker and locate
the next action. Critical permission or misleading-completion mistakes need a
fix and retest; an aggregate satisfaction score cannot hide them.

Report observed outcomes honestly. Five users is useful supporting evidence,
not a mandatory rubric threshold or a guarantee of a particular score.
